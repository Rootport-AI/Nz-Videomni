## 1. なぜこの調査が必要なのか

タイムラインに置いた動画クリップ（リボン）には「**再生位置**」という設定項目があります。リボンの左端を右へドラッグして頭を削ると、この項目に「元動画のどこから再生を始めるか」が記録されます。ところが、この値が**秒で入っているのか、フレーム数で入っているのか**、フレームだとしたら**プロジェクトのフレームレート基準なのか元動画のフレームレート基準なのか**が、AviUtl2の開発キット（SDK。プラグインを作るための資料一式）のどこにも書かれていません。トリム機能は「元動画の何秒目から何秒分を切り出すか」をバックエンドに渡す仕組みなので、この単位が確定しないと**切り出す位置そのものが決められず、機能が成立しません**。単位を推測で実装すると「頭を2秒削ったつもりが60秒目から切り出される」といった、見た目には気づきにくい取り違えが起きます。そこで、実機で実際の値を1回だけ吐き出させて確認する、というのがこの調査です。

## 2. 調査ビルドの作り方

普段のビルドと配置の手順（`README.md` の Build / Deploy 節）と同じで、**ビルドのときに `-ProbeVideoItems` を付けるだけ**です。

```powershell
# 1) 調査用ビルド（-ProbeVideoItems を付ける。それ以外は普段どおり）
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Config Release -ProbeVideoItems

# 2) 配置（普段どおり。AviUtl2 は閉じておく）
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1 -Config Release

# 3) 起動
powershell -ExecutionPolicy Bypass -File scripts\run-aviutl.ps1
```

- ビルド開始時に `*** TEMPORARY video-item probe ENABLED (investigation build - do NOT ship) ***` と表示されれば、調査コードが入った状態です。この表示が出ないときは調査コードが入っていないので、`-ProbeVideoItems` の綴りを確認してください。
- この調査コードは**配布ビルドには一切入りません**。`-ProbeVideoItems` を付けないでビルドすれば、コンパイルの前段階（プリプロセッサ）で丸ごと消えるようになっています。
- **採取が終わったら、必ず `-ProbeVideoItems` なしでビルドし直して配置し直してください。** 調査ビルドはログが非常に多く、常用には向きません。

```powershell
# 採取後：普段のビルドに戻す
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Config Release
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1 -Config Release
```

## 3. ログの場所と読み方

ログファイルは普段と同じ場所です。

```
%LOCALAPPDATA%\NzVideomni\logs\plugin.log
```

エクスプローラーのアドレス欄に上の文字列をそのまま貼り付ければ開けます。文字コードはUTF-8なので、メモ帳やVS Codeでそのまま日本語が読めます。

調査コードが書き出す行はすべて **`[PROBE]`** で始まります。それ以外の行は普段どおりの動作ログなので無視して構いません。`[PROBE]` の行には次の3種類があります。

### 3.1 エフェクト名の一覧（起動後、最初の右クリックで1回だけ）

> **注記（2026-09-01追記）**：**本節と §3.2 に載せてあるログのブロックは、採取をお願いするときに「こういう行が出ます」と説明するために書き手が組み立てた想定の出力例であり、実機で採取された値ではありません。** とくに `effect name="動画ファイル" type=2 flag=3` のような `type=` / `flag=` の数値、`videoFile item name=` の3行、`obj#0 item[再生位置] value="60"` のような値は、**いずれも書式を説明するための仮の値**です（`value="60"` は、直後の読み分けの説明で「フレームだった場合」の例として置いたものです）。
>
> **実際に採取して確定した事実の正本は [`V2V_RIBBON_TRIM_WORKORDER.md`](V2V_RIBBON_TRIM_WORKORDER.md) §4 です**（`再生位置` の生値は4フィールドのCSV `開始,終了,再生範囲,0` で、先頭2値の単位は素材時間軸の秒。ほかに `ループ再生` 項目の実在なども同節にあります）。本書の例示の値は、当時の依頼書の原文として手を加えずに残してあります。

```
[PROBE] ==== probe A begin (TEMPORARY, NZVIDEOMNI_PROBE_VIDEO_ITEMS) ====
[PROBE] effect name="動画ファイル" type=2 flag=3
[PROBE] effect name="画像ファイル" type=2 flag=1
   （…登録されている全エフェクトが1行ずつ続きます…）
[PROBE] videoFile item name="ファイル" type=6
[PROBE] videoFile item name="再生位置" type=2
[PROBE] videoFile item name="再生速度" type=2
[PROBE] enum_effect_item("動画ファイル") returned true
[PROBE] ==== probe A end ====
```

- `effect name=` の行は、AviUtl2に登録されている**エフェクトの正式名称**です。ここに「動画ファイル」がどう綴られているか（例：中黒や空白の有無）を確認します。
- `videoFile item name=` の行が、動画ファイルエフェクトの**設定項目の一覧**です。「再生位置」や「再生速度」という項目が本当に存在するのか、正式にはどう綴るのかがここで分かります。`type=` は項目の種類を表す番号で、`1`=整数、`2`=数値、`3`=チェックボックス、`4`=テキスト、`5`=文字列、`6`=ファイル、といった意味です。
- `returned false` と出た場合は、指定した名前のエフェクトが見つからなかったということです。その行も貴重な情報なので、そのまま報告してください。
- この一覧は**AviUtl2を起動してから最初に右クリックメニューを開いたとき1回だけ**出ます。2回目以降は出ません（ログが膨らむのを防ぐためです）。

### 3.2 選択したオブジェクトの実際の値（右クリックのたび）

リボンを右クリックすると、そのオブジェクトについて次のような行が出ます。`obj#0` の数字はオブジェクトの通し番号です。

```
[PROBE] obj#0 layer=2 frameStart=90 frameEnd=389
[PROBE] obj#0 sectionNum=1
[PROBE] obj#0 itemNameCount=8
[PROBE] obj#0 item[再生位置] value="60"
[PROBE] obj#0 item[再生位置] track@start=60.000000 track@end=60.000000
[PROBE] obj#0 item[再生位置] trackInfo mode=(null) paramNum=1 params=[60.000000] twopoint=0 timecontrol=0 groupNum=1
[PROBE] obj#0 item[再生速度] value="100.0"
[PROBE] obj#0 alias[0]=（エイリアス本文の1〜900バイト目）
[PROBE] obj#0 alias[1]=（901バイト目以降）
```

**この調査でいちばん見たいのは `item[再生位置] value=` の値**です。

- 元動画の頭を **2.0秒**（30フレーム毎秒のプロジェクトで60フレーム）削ったときに、
  - `value="2.0"` のような値 → 単位は**秒**
  - `value="60"` のような値 → 単位は**フレーム**
  - `value="0"` のまま変わらない → この項目には記録されていない（別の項目を探す必要がある）

という読み分けをします。判定の詳細は下の採取ケース表のとおりです。

- `sectionNum=` はリボンの中間点による区間の数です。中間点がなければ `1` になります。
- `trackInfo` の `mode=` は「移動なし／直線移動」などの移動方法の名前、`params=[…]` は区間ごとの設定値です。中間点を打った場合にここが増えます。
- `alias[…]` の行は、そのオブジェクトを「エイリアスとして保存」したときとほぼ同じ内容の全文です。1行が長くなりすぎないよう900バイトずつに分けて出しています。
- ダンプは**AviUtl2の起動から数えて30オブジェクト分**で自動的に打ち切られます。8ケース分には十分足りますが、途中で `[PROBE] obj#` の行が出なくなったらAviUtl2を再起動してください（`plugin.log` は追記されるので、再起動しても前の記録は消えません）。

## 4. 採取していただきたい8ケース

各ケースで、以下の**3点セット**を採ってください。

1. **`plugin.log` の該当部分** — ケースごとに切り分けやすくするため、**1ケース終わるごとに `plugin.log` をコピーしてファイル名を `plugin_R1.log` のように変えて保存**していただけると確実です（元の `plugin.log` はそのままで構いません。追記されていくので、コピーを取っていけば区切りが分かります）。
2. **エイリアスファイル** — 対象のリボンを右クリック →「エイリアスとして保存」で `.aul2` ファイルとして保存し、`R1.aul2` のようなファイル名にしてください。
3. **選択オブジェクトの詳細のスクリーンショット** — そのオブジェクトの設定欄（画面右下の「選択オブジェクトの詳細」。再生位置・再生速度が表示されている欄）を画面キャプチャしてください。ログの生の値と、画面に表示されている値の対応を突き合わせるのに使います。

各ケースの操作は「リボンを右クリックして Nz-Videomni のメニューを開く」（メニュー項目は何も選ばずに閉じてOK）まで行ってください。右クリックした時点でログが出ます。

| # | 素材と操作 | これで何が分かるか |
|---|---|---|
| **R1** | 30フレーム毎秒のプロジェクトに、10秒のmp4を何も加工せずそのまま配置し、右クリック | 何もしていないときの再生位置の値（省略時は0なのか、そもそも項目が出ないのか） |
| **R2** | R1のリボンの**左端を右へ60フレーム（＝2.0秒）ドラッグ**して頭を削り、右クリック | **★最重要。** `2.0` 系の値なら単位は秒、`60` 系の値なら単位はフレーム |
| **R3** | **24フレーム毎秒**のプロジェクトを新規に作り、同じ10秒mp4を置いて**2.0秒相当＝48フレーム**頭を削り、右クリック | フレームだった場合の基準。`48`＝プロジェクトのフレームレート基準、`60`＝元動画のフレームレート基準、`2.0`＝秒、と切り分けられる（元動画が30フレーム毎秒であることが前提） |
| **R4** | R1の再生位置の欄に**キーボードで直接 `100` と入力**して確定し、右クリック | 画面に表示される単位と、ログに出る値の対応関係 |
| **R5** | リボンの**再生速度を200%**に変えて右クリック | 再生速度の項目が実在するか、書式は `200` なのか `2.0` なのか |
| **R6** | リボンに**中間点を1つ**打って（＝2区間にして）右クリック | 区間数（`sectionNum`）と、区間ごとの値の並び（`trackInfo` の `paramNum` / `params`） |
| **R7** | リボンを**元動画より長く**引き伸ばして右クリック | 「リボンが元動画より長いときはトリムしない」判定が正しく成立するかの実証 |
| **R8** | **.mkv または .webm** の素材でR2と同じ操作（頭を2.0秒削る）をして右クリック | mp4以外の拡張子でも同じ挙動になるか |

> 素材について: R1〜R7は**同じ10秒のmp4**（できれば30フレーム毎秒のもの）を使い回してください。R8だけ別素材です。手元に適当な素材がなければ、Nz-Videomniで生成した動画をそのまま使っていただいて構いません（その場合は素材のフレームレートを併せてお知らせください）。

## 5. 採取後の受け渡し

- `plugin_R1.log` 〜 `plugin_R8.log`、`R1.aul2` 〜 `R8.aul2`、スクリーンショット8枚をまとめてお渡しください。
- あわせて、**使用した素材の長さ・フレームレート・解像度**（例: 10.0秒 / 30フレーム毎秒 / 1920x1080）をお知らせください。単位の切り分けに必要です。
- 結果を受け取り次第、`Docs/V2V_RIBBON_TRIM_WORKORDER.md` 第4節の判定表に当てはめて実装方針を確定し、`GetSelectionEditProc`（リボンの状態をWeb画面へ渡す部分）への項目追加と、秒への換算式を実装します。

## 6. この調査コードの撤去について（実装側の備忘）

> **撤去は2026-08-01に完了しました。** 以下に挙げた5か所はいずれも現在のソースには存在しません（`scripts/deploy.ps1` の `[PROBE]` バイト検索ガードだけは、将来また同種の調査ビルドを作ったときの保険として無害なので残してあります）。以下は当時の撤去手順の記録です。

調査コードは以下の5か所にだけ入っており、撤去は機械的な作業です。すべて「TEMPORARY PROBE (V2V ribbon trim, section 4)」のコメントが付いています。

- `CMakeLists.txt` — `option(NZVIDEOMNI_PROBE_VIDEO_ITEMS …)` とその `target_compile_definitions` ブロック
- `scripts/build.ps1` — `-ProbeVideoItems` スイッチとその分岐
- `native/src/plugin.cpp` — `#if NZVIDEOMNI_PROBE_VIDEO_ITEMS` ブロック（プローブA本体）と、`EmitMenuInvoked` / `OnMenuInvokedParam` 冒頭の呼び出し2か所
- `native/src/bridge.cpp` — `#if NZVIDEOMNI_PROBE_VIDEO_ITEMS` ブロック（プローブB本体）と、`GetSelectionEditProc` 内・`Bridge::SetEditHandle` 内の呼び出し2か所

既定（スイッチなし）のビルドではプリプロセッサの段階で完全に消えるため、撤去前でも配布ビルドの中身は撤去後と同一です。
