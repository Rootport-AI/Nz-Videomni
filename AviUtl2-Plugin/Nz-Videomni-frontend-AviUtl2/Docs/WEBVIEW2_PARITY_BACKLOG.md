#### 優先度の付け方の原則（2026-07-15 オーナー方針）

- **ゴールは「Gradio GUIに存在する機能をすべてフロントエンドにも実装すること」。** 以下のN1〜N13のうち、N12（品質モード`two_stage_hq`ラジオ）とN9（ポーリング間隔・タイムアウトのユーザー設定欄）はいずれもオーナー決定（2026-07-15）により将来の研究課題へ降格したため、能動的な実装対象はそれらを除く**11件（N1〜N8・N10・N11・N13）**です。詳細はN12・N9の項目（下記「小粒項目」節）と`Docs/PENDING_TASKS.md`「将来の研究課題」節を参照してください。
- **優先度（着手順）は「機能の重要性」ではなく「実装の難易度と依存関係（順番）」で決めます。** ある機能Aが別の機能Bの土台になっていて、Aが無いとBを設計できないなら、Aの方が先＝優先度が高い、という考え方です。
- したがって本セクションは、旧版の `重要度[中/低]`（＝機能の重要性による分類）という軸を**廃止**し、各項目に **「難易度（小/中/大）」** と **「依存関係」** の2行を持たせ、末尾に **「推奨実装順（段階）」** を新設する形へ組み替えました。以前の「中／低」という重要度ラベルは、この方針のもとでは意味を持たないため削除しています。

書式は **バックエンドGradioの現状 / フロントエンドの現状（file:line）/ 差分 / 難易度 / 依存関係**。バックエンド現状・フロント現状・差分の事実記述（file:line）は従来どおり実コードで裏取り済みのものをそのまま保持し、今回は「難易度」「依存関係」の2行を新たに各項目のコードを読んで裏取りのうえ追加しています。並び（N1〜N13の番号）は識別子として維持し、着手の順序は末尾の「推奨実装順」で表現します。
