# Outputs-archive — 一次記録のスナップショット置き場

**このフォルダは、`outputs/` に置いてある一次記録（実験や計測をしたその場で書いた、いちばん元の記録）のうち、
生きている文書から「正本」として参照されているものだけを複写して保管する場所である。** 本書がこのフォルダの
運用規則の正本であり、複写の要不要はここに書いた基準で判断する。（本フォルダの存在と位置づけは`../STORAGE_POLICY.md`から参照されている）

## 1. なぜ必要か

`outputs/` は git の追跡から外してある（生成した動画そのものが入るため、リポジトリへ入れられない）。
そのため、追跡している文書が「詳細は `outputs/○○/RESULTS.md` を見よ」と書いていても、
**リポジトリを git clone しただけの読者には、その参照先が存在しない**。実機を持っているオーナーの手元でしか
辿れない参照になってしまう。この断絶を埋めるために、参照先の Markdown だけをここへ複写している。

## 2. 何を複写するか（選別基準）

**複写するのは「生きている文書から参照される、そこにしか無い情報」だけである。**

- **複写する**: 台帳（[`PENDING_TASKS.md`](../PENDING_TASKS.md)）・現役の設計書・実行されるコードのコメントなど、
  **いま読まれる側の文書**が正本として指しているもの。読者がその参照を辿れないと、判断の根拠や手順が分からなくなる。
- **複写しない**: 追記専用の記録簿（[`VERIFICATION_LOG.md`](../VERIFICATION_LOG.md)・
  [`PENDING_TASKS_CLOSED.md`](../PENDING_TASKS_CLOSED.md)）**からしか参照されていないもの**。
  これらの記録簿は結論と数値を本文へ転記したうえで一次記録を指しているので、複写しなくても読者は結論に辿り着ける。
  各テーマの実機ゲートの `RESULTS.md` の多くがこれに当たる。
- **対で複写してよい**: 同じキャンペーンの計測台 `README.md`（計測の使い方・窓の定義など、
  `RESULTS` が「正本はそちら」と指している側）は、その `RESULTS` が複写対象なら対で複写してよい
  ——`RESULTS` だけを複写しても、読者は物差しの定義へ辿り着けないためである
  （`comfort-calib-2026-08-31` と `comfort-calib-2026-09-04` の2件がこれに当たる）。

**2026-09-02 の初回選別では、`outputs/` にあった Markdown 49 本を棚卸しして 5 本まで絞った。**
数を増やすことが目的ではない——増やすほど「実機側だけが更新されて複写が古びる」箇所が増えるので、
基準を満たさないものは入れない。

## 3. 複写の作法

- **冒頭にスナップショット注記を置く**。原本のパス（`outputs/…`）と複写日を書き、正本は実機側であることを明記する。
- **本文は原本とバイト単位で同一にする**（注記だけを先頭に足す）。読み比べたときに食い違わないようにするため。
- **原本には手を入れない**。`outputs/` は読み取り専用として扱う。
- **実機側の原本が更新されたら、複写も更新する。** 複写だけを直すことはしない（正本は常に実機側である）。
- **原本の中の相対リンクは書き換えない。** 複写した位置からは解決できないリンクが残るが、冒頭注記に原本のパスが
  書いてあるので、実機を持っている人はそこから辿れる。リンクを書き換えると本文がバイト同一でなくなるため、
  そちらの一貫性を優先している。

## 4. 今後の運用

`outputs/` の中に「生きている文書から正本として参照される Markdown」を新しく作ったときは、
**そのときに本フォルダへの複写もセットで検討する**（あとからまとめて棚卸しすると、参照だけが先に増えて
読者に届かない期間ができる）。参照する側が追記専用の記録簿だけであれば、複写は不要である。
