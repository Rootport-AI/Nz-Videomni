### 5.3 第2次（サーバー既定の腕）との突き合わせ

## 6. 対照実験 H4′（拡張なしの対照）

**問い**: 反転は「画角拡張」のせいか、それとも同じキャンバス・同じ尺なら拡張が
無くても起きる「生成そのものの天井」（§4-34 の復号の天井）なのか。

2.3 の反転点 177f と**まったく同じキャンバス・同じフレーム数で、拡張だけを外した**
点を測りました（`plan_T_t2v`。t2v の対照は自分自身の基準点 `oa_c2_121_t2v_23` を持ち、
画角拡張の基準点とは比べません。比べてしまうと、対照が切り分けたい差そのものが
測定に混ざるからです）。

| 177f・1920×1024 | stage2 窓の共有中央値 | 自分の基準比 | v3′ |
|---|---:|---:|---|
| **拡張あり**（画角拡張） | 1,917.3 / 1,994.8 MB | +769.9 / +847.4 MB | **plateau** |
| **拡張なし**（t2v 対照） | 1,126.8 MB | **−17.2 MB** | **clean** |

**結論: H4′ は棄却されます。** 同じ画素数・同じ尺でも、拡張を外すと共有メモリは
基準点と変わりません。反転は画角拡張そのものが持ち込む負荷（元動画の符号化と
拡張マスク）によるもので、キャンバスの大きさの副作用ではありません。

→ この線は `OUTPAINT_COMFORT_TOKEN_BUDGETS`（画角拡張専用の表）に置くのが正しく、
単発生成の予算と混ぜてはいけない、という現行の設計判断を**実測で裏づけました**。

## 7. 異常・想定外（朝の判断 J3 の材料）

### 7.1 2.3 の 185f だけ v1／v2 と v3′ が食い違う

`oa_c2_185_23` は v3′ が `plateau`、v1／v2 が `organic` でした。原因は判定軸の違いで、
記録上の矛盾ではありません。

- `axis1b`（共有メモリが基準比 +300MB 超）= **真**（2,621 MB 対 基準 1,147 MB）
- `axis3`（stage-2 が20%以上遅い）= **偽**（秒/トークン 1.08倍。閾値 1.20倍）

つまり**メモリは膨らんだが速度は落ちなかった**点です。裏づけとして、この点の
stage-2 窓の PCIe p90 は 128 MB/s しかなく、両隣の 177f（21,189）・193f（27,274）と
桁が違います。退避は起きているが、この点では実行時間に響かなかった、と読めます。

**境界の採否には影響しません。** §3-7 の「食い違いは境界に採らない」規則は
**v3 と v3′ の食い違い**についての規則で、185f では v3（stage2＋復元の2窓）も
`plateau` なので v3 と v3′ は一致しています。加えて 185f は境界の端ではありません
（境界は 169f と 177f）。

### 7.2 2.3 の stage-2 窓が「全点で判定不能になる見込み」は外れた

第2次 README §5.3 は「2.3 の画角拡張の第2段階の窓は、全点で判定不能になる見込み」
（2ステップ・約6.4秒で標本が7前後）と書いています。**本キャンペーンでは全点で
判定可能でした**（標本 16〜62）。

これは第3次で変わったのではなく、**第2次のデータでも既にそうなっていました**
（第2次の C2 の点でも stage-2 は 53〜129秒・標本 27〜64）。あの見込みは
2026-08-11 の小さなジョブ（2ステップ・6.4秒）を根拠にしたもので、C2 の大きさの

## 10. 再現の手順

```
.venv\Scripts\python.exe selftest\parser_selftest.py     （GPU不要・79件）
.venv\Scripts\python.exe selftest\analyse_selftest.py    （GPU不要・43件）
.venv\Scripts\python.exe calib.py preflight              （GPU不要・全計画）
.venv\Scripts\python.exe make_results.py                 （本記録の表を作り直す）
```

計測をやり直す場合の順序は README §5 の計画表と第2次 README §7.3 のとおりです。
**再走は必ず別ラベル**にしてください（同一ラベルの再実行は `runs/<ラベル>/` を
上書きし、基準点が乗り換わる事故になります）。`mkplan.py` はこの規則を機械的に
守らせるため、既に走ったラベルの生成を拒否します。
