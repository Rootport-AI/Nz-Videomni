正解として使った Y の BF16 について: X の int8 は、Y の BF16 を行ごとの最大値÷127 で量子化し直した値と、全要素で ±1 以内に一致した（完全一致は 93.6〜94.7%）。また 127×倍率 ÷ 行の |W_Y| の最大 は 0.996〜1.004 だった。したがって、Y の BF16 は X の量子化前の値とみてよい（§5）。

## 2. 入力と計算式の出典

### t_emb
- `engine_h3/dit.py:580-592` の `adaln_embed` と同じ式で作った。
  - `pos = clamp(t,0,1)*(G-1)`
  - `i0 = floor(pos).clamp(max=G-2)`
  - `lerp(table[i0], table[i0+1], pos-i0)`
- docstring に `t = 1 - sigma` とあるので、σ = 1.0・0.75・0.5・0.25・0.02 は t = 0・0.25・0.5・0.75・0.98 になる。表の位置は 0・256・512・768・1003.52。
- 形は [5, 8] の f32。`adaln_t_table` は X と Y でビット単位まで同一（F32 [1025,8]）。

### 4 通りの計算
- **正解**: `F.linear(t, W_Y(BF16→f32), b_Y(F16→f32))`
- **今の計算**: `dit.py:316-319` と同じ。`F.linear(t.f32, W_X(int8).to(f32), b_X.to(f32))`
- **方法 A**: `F.linear(t, W_X.float()*weight_scale, b_X)`
- **方法 B**: comfy-kitchen の eager の `int8_linear`（`comfy_kitchen/backends/eager/quantization.py:985-1080`）の、convrot=False の場合を同じ式で再現した。
  - 入力の量子化は `quantize_int8_rowwise`（:858-877）に従う。
    - `scale = (amax(|x|, 行)/127).clamp(min=1e-30)`
    - 倍率が 0 の行は `finfo.tiny` に置き換える（:816-820）
    - `q = round(x/scale).clamp(-128,127)`（`_round_int8`、:823-828。round は偶数への丸め）
  - 積は int32 で累積し（`_int8_matmul_accumulate`、:750-782）、`acc.float() * (x_scale * weight_scale)` を out_dtype に直してから bias を足す。
  - out_dtype は入力の dtype、つまり f32（`tensor/int8.py:282-294`）。
  - CUDA の量子化は `v * (1/scale)` に `cvt.rni.sat.s8.f32` を掛ける形（`backends/cuda/float_utils.cuh:39-54`）。これも別に再現し、eager と量子化後の入力が完全に一致すること、出力の差が 0 であることを確かめた。
  - CUDA の GEMV 本体（`_C.int8_gemv_dequant`）はソースが無いので、確かめていない。
- **comfy-kitchen を import しなかった理由**: パッケージの `__init__.py` が `backends.cuda`（`_C.abi3.pyd`）を読み込み、`registry.py:33` に `torch.cuda.is_available()` がある。そのため直接は呼ばず、式だけを再現した。

### 塊の分け方
- `dit.py:320-322` は `view(M*3, 6*5376).chunk(6)` なので、出力 [M, 96768] を [M, 3（modality の札）, 6（塊）, 5376] として扱った。
- 塊の順は `dit.py:375` の shift_msa・scale_msa・gate_msa・shift_mlp・scale_mlp・gate_mlp。
- 指標は 5 時刻と 3 つの札をまとめて計算した。

## 6. 手順 7: Y の中間のブロックの adaln の由来

- Y のブロック 10 の adaln は、int8・倍率とも X のブロック 10 とビット単位で同一。bias だけが F16 の最下位の桁で違う（相対差 1.8e-4）。
- 方法 A の出力どうしでは、相関 1.0000000、相対差 1.9e-4。

**1 行の手がかり: Y の中間のブロックの adaln は X と同じ重み（Sulphur-3 側）に由来し、公式の Ref2VA の値ではない。** R とは近いが、Y・X の一致（相対差 1.9e-4）より 2 桁離れている。そのため Y も、ブロック 2〜48 では X と同じ「倍率が掛からない」問題を抱える（数値上の帰結。製品で実際に動かしての確認はしていない）。

## 7. 注意と限界

- 照合したのは adaln_proj の出力（変調量）だけ。これが画面上のブロック状のノイズの直接の原因かどうかは、この照合の範囲外。ただし、変調量が 2〜133 倍に崩れることは数値で確かめた。
- 方法 B は、eager の式と CUDA の量子化の式を再現したもの。CUDA の GEMV の本体（`_C`）はソースが無く、確かめていない。int32 の累積に倍率を掛ける順序の違いがあっても、差は f32 の丸め程度と見る（推測）。
- 時刻は σ との対応を docstring（t = 1−σ）に従って決めた。スケジューラーが実際に出す σ の列そのものは使っていない。
