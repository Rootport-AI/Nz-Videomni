# MiniMax H3 の Sol-H3-VAE を製品に入れる段 1 の、実機の確認（2026-11-23〜24）の出典

Sol-H3-VAE（MiniMax H3 の動画VAE の復号器を 24 層に蒸留した、復号専用の軽い復号器）を製品のコードに入れた段 1（サーバー側）の、実機の確認（GPU。項目 S1〜S10）の台本と記録の写しを置く保管庫です。確認の条件・数値・結論の正本は記録簿 `Docs/VERIFICATION_LOG.md` §229、設計の正本は設計正本 `Docs/MINIMAX_H3_DESIGN.md` の裁定 108 と §6.8 にあり、ここには書きません。

**これは 2026-11-24 の時点の写しです。** 最初に写したあと、S8 の対照（`S8_off`。同じ条件で Sol を指定しない 1 本）を終えた時点で、台本・一覧を写し直し、対照の記録と比較の記録を足しました。元のフォルダは git の追跡外の `outputs/h3-sol-gates-2026-11-23/` で、正本は常にそちらです。回すときは元のフォルダの台本を使ってください（使い方は `SCRIPT_README.md` と `h3_sol_gates.py` の冒頭の説明にあります。GPU を使う項目は、その都度オーナーの了承を得てから回します）。

## 台本（中身を変えずに写したもの）

- `h3_sol_gates.py` — 確認の本体（対照の項目 `S8_off` を足した版を写し直した）。アプリ側の仮想環境で動き、torch を読み込みません。項目ごとに一時の設定と専用のポートでバックエンドを起動して止め、各項目の前に、オーナーのサーバー・エンジンのワーカー・GPU の使用量を確かめます。バックエンドの起動と停止・記録の書き出し・利用者のフォルダーを含むパスの消去は、pi-H3 の確認の台本（保管庫 `Docs/Outputs-archive/h3-pih3-gates-2026-11-23/` の `h3_pih3_gates.py`）を読み込んで使います。
- `compare_s8.py` — S8 と S8_off の記録（`result.json`・`wddm.csv`）から、主な時点の共有 GPU メモリ・ステップの間隔・専用の GPU メモリの山・復号の段を並べた `s8_compare.json` を作る部分（GPU を使わない）。
- `engine_items.py` — エンジンを直接呼ぶ項目（S1・S6・S9・S10）。エンジンの仮想環境で、`h3_sol_gates.py` から起動されます。
- `wddm_sampler.ps1` — 共有 GPU メモリの採取（実験 `h3-sol-spike-2026-11-23` と同じもの）。
- `SCRIPT_README.md` — 元のフォルダの `README.md` の写し（ファイルの役割・実行のしかた）。

## 記録の写し

- `summary.md`・`summary.json` — 10 項目と対照の S8_off の判定と、合格の条件の一覧（写し直し）。
- `s8_compare.json` — S8 と S8_off を並べた数値（記録簿 §229.11 の表の元）。
- `dry_run.json` — GPU を使わない確認（要求の組み立て・ファイル・記述子の写し）の記録。
- `runs/<項目>/result.json` — 項目ごとの記録（`S1`〜`S10` と、名指しでだけ動く対照の `S8_off`）。エンジンを直接呼んだ項目は、エンジンの記録をこの中に含みます。
- `runs/S8/wddm.csv`・`runs/S8_off/wddm.csv`・`runs/S10/wddm.csv` — S8・S8_off・S10 のあいだに約 1 秒おきに採った、専用の GPU メモリと共有 GPU メモリの値（列は時刻・専用・共有・前の採取からの間隔）。S8 と S8_off の共有 GPU メモリが増えた時点（記録簿 §229.11）は、この表から読みました。
- `runs/S10/marks.json` — S10 の 2 つの復号の、始まりと終わりの時刻。

写したファイルは、元のファイルとバイト単位で同じです。台本は、GPU を使っているプロセスの数だけを記録し、記録に書くパスから利用者のフォルダーを消す作りです。写す前に、利用者名・利用者のフォルダーを含むパス・メールアドレスが含まれていないことを確かめました。

## 写さなかったもの

- 動画（`runs/<項目>/` の mp4）、並び画像（`sheets/`）、項目ごとの `metadata.json` とサーバー・ワーカーのログ、エンジンを直接呼んだ項目の補助の記録（`engine.json`・`console.log`）、`logs/` のログ、一時の実行環境（`_rt/`・`_dry/`）は写していません。大きすぎるか、リポジトリに入れない慣行の物です。元のフォルダにだけあります。
- S6 の素材（`_material/broken_sol_first64MiB.safetensors`。実物の Sol の重みの先頭 64 MiB の写し）は、重みの一部なので写していません（Sol の重みは再配布しない。設計正本の裁定 108 ④）。
- V2V と Inpainting の項目（S2）で使った元の動画とマスクは、写していません。
