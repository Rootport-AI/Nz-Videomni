## B. 指摘

### M-1【Major】3-G1 の「2 回目は全部 SKIP」が、freeze を更新したあとの状態を証明しない

- **該当**: 計画 §5 の 3-G1、§6 の進め方（「3-G1 → 3-G2 → freeze の比較と更新」）、§3.1 の B10。
- **根拠【事実】**: 完了の印は `Get-EngineStateHash(freeze の有効行＋直接ピン)` の値である（`install_ltx.ps1:1419`）。§6 の順序では、3-G1 の 2 回目の実行（SKIP の確認）は freeze を更新する**前**に行う。freeze のピンの行が 1 行でも変われば、開発機の印は古くなる。次の実行は「the pinned dependency set changed」の当て直しに入る（`:1437-1438`）。
- **帰結**: コミットする freeze について、冪等性（2 回目は全部 SKIP）の証拠が無くなる。当て直し自体は無害な見込みだが、門の主張と、コミットしたものが一致しない。
- **直し方**: freeze を更新したら、`install-MiniMaxH3.bat` をもう 1 回実行する。1 回目で印が書き換わり（当て直し）、2 回目で全部 SKIP になることを 3-G1 の追記として記録する。または、freeze の比較と更新を 3-G1 の 2 回目より前に置く。

### M-2【Major】freeze を取り直すときの比べ方（正規化）が決まっていない

- **該当**: 計画 §3.1 の B10、§8 の 1。
- **根拠【事実】**:
  - 既存の 3 つの freeze はどれも、直接ピンを `name==version` の素の形で書いている。例: `sageattention==2.2.0+cu130torch2.10.0andhigher.post6`（`engine_h3/venv-engine-h3.freeze.txt` の該当行）、`engine25/venv-engine-ltx25.freeze.txt:104`、`engine/venv-engine.freeze.txt:82`。H3 の freeze の METHOD 欄には、手で正規化した 2 行のことが書いてある（同ファイル冒頭 `METHOD` の段落）。
  - 段 (b) で行を除く条件は `^(torch|torchvision|sageattention)==` である（`install_ltx.ps1:1349-1350`）。
  - 段 (a) では、freeze に無いパッケージが入って残ることがある。前例は `.venv-engine` の `hf-xet` で、段 (a) で入り、freeze に無いため残った（記録簿 §82.7「あわせて観察したもの」の 1）。
- **【推測】**: URL で入れた wheel について、`uv pip freeze` は `sageattention @ https://…` の形で出す。そのため、出力をそのまま比べると、sage の行は毎回「違う」になる。逆に、段 (b) は freeze に書かれた版を `==` でそのまま入れる。だから、freeze にあるパッケージの**版**が uv 0.6.4 と 0.11.32 で食い違う余地は、ほぼ無い。実際に起こりうる差は、(i) sage の行の書き方と、(ii) 段 (a) が残した freeze に無いパッケージ、の 2 つに絞られる。計画 §8 の 1（「解決結果が違う可能性」）が心配している版の差は、仕組みのうえではまず起きない。
- **直し方**: B10 に比べ方の決まりを 2 行足す。(1) 直接ピンの行は `name==version` に正規化してから比べる。(2) freeze に無いパッケージが増えていたら、その一覧を記録簿に書き、freeze に足すかどうかを監督が決める（足せばハッシュが変わる。M-1 と連動する）。生の `uv pip freeze` の出力をそのまま freeze にしない、と明記する。

### M-3【Major】退避先の `.venv-engine-h3.stage1/` は git の無視の対象から外れる

- **該当**: 計画 §3.1 の B9。
- **根拠【事実】**: `.gitignore` の 16 行目は `.venv-engine-h3/` だけで、`.venv*` のような広い型は無い。`git check-ignore -v .venv-engine-h3.stage1/x` の結果は空（無視されない）だった。
