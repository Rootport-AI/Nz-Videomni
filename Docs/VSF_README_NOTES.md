## 1. VSFとは何か

VSF（Value Sign Flip、arXiv:2508.10931）は、**CFG（classifier-free guidance）を使わずにネガティブプロンプトを効かせる手法**の1つです。本プロジェクトでは、同じ目的のNAG（Normalized Attention Guidance）に続く第2方式として実装しました。LTX 2.3の蒸留モデルはCFGが最初から無効（8ステップ・guidance_scale=1.0固定）なので、通常のネガティブプロンプトが使えません。この穴を埋めるのがNAGとVSFです。

2つの方式は仕組みが対照的です。

- **NAG**: 注意計算（attention）を「正のプロンプト用」と「負のプロンプト用」の**2回**行い、両者の出力を正規化つきで混ぜ合わせる。
- **VSF**: 正と負のプロンプトを連結して**1回**の注意計算に混ぜ込み、負の側の値（V, value）だけ符号を反転（−scale倍）する。

計算回数だけ見ればVSFの方が軽い方式です。ただし後述のとおり、この「1回に混ぜ込む」という設計こそがVSFの性格——強い排除力と、その代償——を決めています。

## 2. 中核の仕組み: 注意の「奪い合い」

VSFの本質は、正と負が**1つのsoftmaxを共有する**ことにあります。

注意計算では、生成中の各ピクセル（クエリ）が「プロンプトのどのトークンをどれだけ参照するか」をsoftmaxで配分します。この配分は必ず**合計1**です。VSFでは正と負のトークンが同じ土俵に乗るため、負のプロンプトが注意を3%奪えば、正のプロンプトの取り分は必ず3%減ります。つまり——

> **排除力と忠実度が、同じ財布から支払われる。**

負のプロンプトの効き（排除力）を強めるほど、正のプロンプトが画を支配する力（忠実度）は確実に削られます。これはバグではなくVSFの構造そのものです。

NAGにはこのトレードオフがありません。正と負を別々に計算するので、負をどれだけ強くしても正の注意配分は無傷で、さらに出力を混ぜる際の正規化が暴走の防波堤になります。論文が定性的に主張する「VSFは排除力が強いが、正への忠実度はNAGが上」は、この機構の違いから直接説明できます。

## 3. LTX 2.3固有の事情: 1024対12の不均衡

実装してみると、LTX 2.3ならではの事情が2つ見つかりました。

**(a) 正の側は常に1024トークン。** LTX 2.3のテキストエンコード経路では、プロンプトの実トークンの後ろが「学習済みのregister埋め込み」で1024トークンまで埋められます。これはゼロ埋めのパディングではなく**実データ**です。一方、負のプロンプトは十数トークンしかないので、実トークン部分だけを切り出して連結します（registerまで符号反転すると、プロンプトと無関係な強い反発が混入してしまうため。これは論文も品質劣化要因として明言しています）。

**(b) 結果として注意の奪い合いは1024対12。** 素の状態で負が奪える注意の割合（ログでは `VSF m=...` として計測）は**約1%**しかありません。VSFが実証されたWan 2.1は正負がほぼ同じ長さだったので、LTXでは「効きが弱すぎるのでは」というのが実装前の最大の懸念でした。実測では、1%でも96モジュール×8ステップで積み重なるため**scale 1.5〜5の範囲で目に見えて効く**ことが確認でき、懸念は「効かない」ではなく「軽く効く」方向に収まりました。

## 4. 「3方向のデバッグ」— AdaLN問題

実装中もっとも答えの見えなかった論点です。

LTX 2.3では、正のプロンプト情報は注意計算に渡る直前に**AdaLN変調**（生成の進行度に応じたスケール・シフト補正）を毎ステップ受けています。ところが後から注入する負のプロンプトは、この補正を受けていない「生」の状態です。NAGは正負を別計算するのでこの非対称が無害でしたが、VSFは両者を同じsoftmaxに乗せるため、スケールの不一致が計算を歪める恐れがありました。論文はこの論点に完全に無言。そこで3通りを実装し、実機で比較しました。

1. **raw（生のまま）** — 負は補正せず生のまま混ぜる。NAGと同じ非対称。
2. **modulated（負も変調）** — 負にも正と同じ補正を掛けてスケールを揃える。
3. **v_scale（折衷案）** — 注意の向き先（K）は生のまま、値（V）だけ補正のスケールを掛ける。

**結果**: 実用域のscale 5で比較したところ、3方式とも綺麗に収束し、差は「プロンプトからのズレ（ドリフト）」に現れました。「夕日の波打ち際」だけを指示したのに、rawは女性が1人現れる程度、modulated/v_scaleは会話する女性2人（modulatedは透かし風ロゴまで）出現。ログの実測でも**modulatedは負への注意を約4倍に増やす**ことが確認でき、「負への注意が増えるぶん、正からの逸脱も強まる」という§2の財布の理屈と完全に整合しました。

**採用はraw**です。ズレが最小で、しかもNAGと同じ非対称構成——つまり一番シンプルな作りが一番素直に動きました。確定後、3方式切替のデバッグスイッチはコードから完全に撤去し（引き算の原則）、撤去前後で生成結果が1ビット単位で一致することも確認済みです。実験の経緯はgit履歴と§41.9に残っています。

## 5. scaleの意味と実用指針

最終的にVSFのつまみは `vsf_scale`（0〜10・既定1.5）の1本です。§2の構造から、このつまみは**効きの強さと忠実度のトレードオフを直接動かす**ことに注意してください。

- **既定1.5**: 論文（Wan 2.1実測1.7）に準拠した控えめな値。高品質のまま軽く効く。
- **実用域は1.5〜5**: 5ではネガの排除力がはっきり出る（実機で「long hair / black hair / short sleeves」の排除を確認）一方、場面や人物が変わる意味ドリフトの代償が出はじめる。面白い現れ方として、実写指示が**2Dアニメ調に様式転換**する例も観察された（「blurry, low quality, distorted」から遠ざかる圧が、ノイズやボケの少ないフラットな絵に押し出したと解釈できる）。
- **15以上は崩壊**: 8ステップ蒸留では収束せずノイズになる。VSFにはNAGのような再正規化が無いため、共有softmaxに大きな負のVを混ぜるほど出力のノルムが崩れる。論文の実証レンジ（≤10）の外はやはり使えなかった。
- **0は「無効」ではない**: scaleを0にしても負のトークンがsoftmaxの取り分を奪う効果は残る。無効化はチェックボックスをOFFにすること。

## 6. NAGとVSFの使い分け（README向けの要約案）

| | NAG | VSF |
|---|---|---|
| 仕組み | 注意計算2回＋正規化つきで混合 | 1回の注意計算に混ぜ込み・負のVを反転 |
| 排除力 | 中 | 強（scale次第） |
| 正プロンプトへの忠実度 | 高（構造的に守られる） | scaleを上げるほど低下 |
| 調整パラメータ | scale / tau / alpha の3つ | scale 1つ |
| 向く場面 | 構図やプロンプトを崩したくないとき | 特定の要素を強く追い出したいとき |
