# Dependency snapshot of .venv-engine-ltx25 (LTX 2.5 engine worker interpreter).
#
# WHY: this is the reproducibility record for the known-good LTX 2.5 engine venv,
# the exact sibling of engine/venv-engine.freeze.txt for the 2.3 engine. There is
# no uv.lock for either. Rebuild reference: engine25/engine25-venv-pyproject.toml.
#
# WHY A SECOND ENGINE VENV EXISTS AT ALL: official LTX-2 v1.2.0 needs
# transformers 5.x (Gemma 4) and the 2.3 engine is pinned to transformers 4.57.6.
# One interpreter cannot hold both, so .venv-engine and .venv-engine-ltx25 are
# built side by side and never import each other's packages.
#
# METHOD: generated via importlib.metadata (enumerating installed *.dist-info in
# .venv-engine-ltx25/Lib/site-packages), the same method used for the 2.3 freeze.
# `pip` and `uv` are BOTH absent from this uv-built venv, so `pip freeze` /
# `uv pip freeze` were not available; the dist-info enumeration is the
# exact-installed equivalent (name==version).
# Interpreter: CPython 3.12.9  (.venv-engine-ltx25/Scripts/python.exe)
# Captured: 2026-08-21
#
# NOTE: two distributions are git direct-url installs (NOT PyPI); their lines
# below are bare 'name==version' pins, so the exact source rev is recorded here
# for reproducibility. Both come from ONE commit -- official LTX-2 v1.2.0:
#   ltx-core:      git+https://github.com/Lightricks/LTX-2.git#subdirectory=packages/ltx-core
#                  @ d151147788a9284cca791edc6ce898007e727fe6
#   ltx-pipelines: git+https://github.com/Lightricks/LTX-2.git#subdirectory=packages/ltx-pipelines
#                  @ d151147788a9284cca791edc6ce898007e727fe6
# See scripts/install_ltx.ps1's $ltx25DirectPins for the authoritative pins.
#
# NOTE: torch and torchaudio are ALSO listed in $ltx25DirectPins (and so are
# filtered out of the plain `-r freeze` install), unlike the 2.3 stack where
# only the git/wheel pins are. Reason: the direct-pin stage is a real resolve,
# and without them uv fetches whatever the cu128 index calls newest (~2.11,
# several GB) only for the freeze stage to downgrade it straight back to 2.9.1.
# Their '+cu128' local versions are load-bearing on BOTH lines -- torchaudio left
# unbounded was measured resolving to 2.11 and dragging a matching torch with it.
#
# NOTE: opencv-python-headless and torchvision are the engine/preprocess
# dependencies (cv2 does every canny/dwpose/depth frame op; torchvision is used
# only by the VDA depth wrapper's Compose), added 2026-08-24 so the 2.5 engine
# can build IC-LoRA control videos with the same code the 2.3 engine runs.
# cv2 4.13.0.92 was verified ABI-compatible with this venv's numpy 2.5.2.
#
# NOTE: no diffusers and no natten here, and that is deliberate -- see the
# header of engine25/engine25-venv-pyproject.toml for the reason each one is
# out. TWO packages used to be on that list and no longer are:
#   triton-windows  added 2026-08-24, because the 2.5 engine runs the same fused
#                   GGUF K-quant dequantisation kernels the 2.3 engine does
#                   (engine/gguf/dequant_triton.py), and those need Triton.
#   sageattention   added 2026-08-25 (Acceleration third wave), because
#                   `attention_backend: "sage"` is now a per-job option on the
#                   2.5 engine too -- engine/transformer/sage_attention_service.py
#                   is shared by both engines, so this venv needs the wheel it
#                   imports. Its line below is BARE (name==version), like the
#                   ltx-core / ltx-pipelines / torch / torchaudio lines, because
#                   there is no PyPI build of it at all: it comes from the direct
#                   wheel URL in scripts/install_ltx.ps1's $ltx25DirectPins,
#                   which is the identical URL the 2.3 stack pins (one cp310-abi3
#                   wheel, both venvs). triton-windows is its runtime JIT here as
#                   well as the dequantisation kernels'.
# OpenImageIO, by contrast, is present and unavoidable: `ltx_pipelines.distilled`
# imports it transitively, and a real Windows wheel exists (3.1.16.0 / cp312 /
# win_amd64), so no stub is needed.
#
